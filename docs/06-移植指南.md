## 3. 启动链原理

```
上电 → XBL → ABL（小米魔改高通 UEFI，kernel:uefi）
   ↓ 读活动槽（a/b）的 boot + vendor_boot
   ↓ 校验 boot v3 header 结构
   ↓ 从 vendor_boot 取 DTB，按 qcom,msm-id + qcom,board-id 匹配
   ↓ 加载内核 + ramdisk + dtb → 跳转
内核 → initramfs /init → 挂 userdata（ext4）→ switch_root → systemd
```

### 三个必须知道的规则（踩出来的）

1. **boot 镜像必须用原厂 boot v3 壳**
   从零生成的 header 会被 ABL 拒绝。做法：拿原厂 `boot_a.img`（192 MB）当模板，
   只替换 kernel/ramdisk 段，保留 header 的 `os_version`、`header_version`、`page_size`。
   参考 `04-tools/pack_dagu_p0.py`。

2. **DTB 必须带 `__symbols__`，且必须配合法 stub DTBO**
   - 编译时 `make DTC_FLAGS="-@"`（否则 overlay 无法应用）
   - 需要刷一个合法 dtbo（`dtbo-stub.img`，1 个 overlay，`board-id = 0x33`）
   - **`fastboot erase dtbo_b` 在 dagu 上无效**（与 elish 不同），必须提供 stub

3. **`fastboot boot` 不可信**
   实测传 4 KB 随机内核与正常镜像行为一致 → `fastboot boot` 很可能不真正执行传入镜像。
   **所有验证都用落盘引导**（`flash boot_b` + `reboot`）。

| 项 | elish | dagu | 说明 |
|---|---|---|---|

## 5. Rootfs 与桌面

- Debian 13 trixie arm64，做成 **1.5 GiB ext4**（`images/rootfs-1.5g.img`），只用了 ~640 MB
- 作者 initramfs 的 `/init` 会：
  1. 扫 `/sys/class/block` 找分区名 `userdata`（fallback `/dev/sda34`）
  2. `e2fsck + resize2fs` 把 1.5 GiB 扩到整个分区（105 GiB）
  3. `mount ext4`，检查 `/sbin/init`，`switch_root`
  4. 把 `venus.ko` 放到 userdata（**但不会自动 modprobe，需要自己加载**）
- 桌面：`gnome-core` + `gdm3`，中文（`zh_CN.UTF-8` + `fonts-noto-cjk` + `ibus-libpinyin`）
- 额外：`firefox-esr`、`wps-office`（ARM64 deb，2.6 GB）、`alsa-utils`、`i2c-tools`、`mesa-utils`

## 6. 固件补齐

**这是移植里最容易被忽略、也最容易翻车的一步**：Debian rootfs **完全不带高通固件**。

### 6.1 ADSP / Venus（从设备 modem 分区取）

```bash
# 设备上
mkdir -p /mnt/modem
mount -o ro /dev/sde5 /mnt/modem          # modem_a，vfat
ls /mnt/modem/image/                       # 这里面有 adsp.* venus.* slpi.*
mkdir -p /lib/firmware/qcom/sm8250/xiaomi/dagu
cp /mnt/modem/image/adsp.* /mnt/modem/image/venus.* /lib/firmware/qcom/sm8250/xiaomi/dagu/
du -sh /lib/firmware/qcom/sm8250/xiaomi/dagu/     # 必须约 20 MB，不能是 0！
```

> ⚠️ **坑**：如果 `mount` 没成功（挂载点空），`cp` 会生成一堆 **0 字节文件**且不报错。
> 复制后**必须** `ls -la` 看大小、`du -sh` 看总量（正常 20 MB）。

### 6.2 蓝牙（Debian 源）

```bash
# PC 下载（GitHub raw / kernel.org 在国内会超时，用 sources.debian.org）
curl -O https://sources.debian.org/data/non-free-firmware/f/firmware-nonfree/20260916-1/qca/htbtfw20.tlv
curl -O https://sources.debian.org/data/non-free-firmware/f/firmware-nonfree/20260916-1/qca/htnv20.bin
# 传到设备 /lib/firmware/qca/
```

校验值：
```

htnv20.bin      5,857 B  md5 74ac04b7aa5e8d988e4813f6d9a20094
```

加载成功的日志：

```
Bluetooth: hci0: QCA Downloading qca/htnv20.bin
Bluetooth: hci0: QCA setup on UART is completed
```

### 6.3 GPU / 摄像头固件
`vendor` 分区（super 内）的 `/firmware/` 已包含（a650_gmu.bin、a650_sqe.fw、a6xx_zap.*），
本系统里已就位，无需额外处理。

### 6.4 SLPI（尚未补）
`slpi.mbn` 仍是 8 KB 占位（日志 `slpi.mbn failed -2`）。补上可能改善 ADSP 子系统稳定性，
但不是必需（Wi-Fi/BT/音频都不依赖它）。

### 6.5 国家码 / regulatory.db（已内置进 boot）

**为什么要做**：默认 `country 00: DFS-UNSET`，5 GHz 全部锁在 **6 dBm / 20 MHz / PASSIVE-SCAN**，
而 `cfg80211` 在开机 **3.2 秒**（initramfs 阶段）加载 `/lib/firmware/regulatory.db`，
那时 userdata 还没挂载 → `-2 ENOENT` → `iw reg set CN` 因为没有国家表而被静默忽略。

**做法（已包含在本包的 boot-dagu.img 里）**：

1. 在 `vendor_boot` 的 cmdline 里追加：
   ```
   cfg80211.ieee80211_regdom=CN
   ```
2. 把 **上游签名版** regdb 塞进 boot 的 initramfs（`/lib/firmware/`）：
   ```
   regulatory.db        ← 必须用 regulatory.db-upstream（6380 B）
   regulatory.db.p7s    ← 必须用 regulatory.db.p7s-upstream（1085 B）
   ```
   > ⚠️ **不能用 Debian 签名版**（`regulatory.db-debian` / `.p7s-debian`，1118 B）：
   > 内核只带 upstream 的公钥，Debian 签名会报
   > `cfg80211: loaded regulatory.db is malformed or signature is missing/invalid`

3. 重打包 initramfs → 重打包 boot → 刷 `boot_b`

**效果**：
```
country CN: DFS-FCC
(2400 - 2483 @ 40), 20 dBm
(5150 - 5250 @ 80), 23 dBm, NO-OUTDOOR
(5250 - 5350 @ 80), 20 dBm, DFS
(5725 - 5850 @ 80), 33 dBm
```

**160 MHz 在本机型上不可达（两条硬限制）**：
- **CN 法规**：三条 5 GHz 频段上限都是 `@ 80`（5725-5850 只有 125 MHz，装不下 160）
- **ath11k HE 能力**：`HE RX/TX MCS and NSS set <= 80 MHz`（`iw phy phy0 info` 可见），
  只有 VHT 标称支持 `160Mhz (1/2 NSS)`，但路由器协商的是 HE
- 实际峰值 **864/960 Mbit/s @ 80 MHz HE 2×2**（理论 1201），这就是境内上限

**重打包 initramfs 的正确姿势**（踩过的坑）：
```bash
# 解包
mkdir rd && cd rd && gzip -dc ../ramdisk.gz | cpio -idm --quiet
# 放入 regdb（上游签名版）
cp regulatory.db-upstream lib/firmware/regulatory.db
cp regulatory.db.p7s-upstream lib/firmware/regulatory.db.p7s
# 重打包：必须校验条目数和 gzip 完整性
find . -print0 | cpio --null -o -H newc -R root:root | gzip -9 > ../rd.gz
gzip -t ../rd.gz && gzip -dc ../rd.gz | cpio -t | wc -l   # 条目数必须对得上
```
> ⚠️ 曾出现 **cpio 流被截断但 gzip 校验通过**的假阳性：刷进去后 ABL 直接回退 a 槽。
> 判据不是 `gzip -t`，而是 **`cpio -t | wc -l` 的条目数**（原包 166，加 regdb 后 168）。

**AVB footer 注意**：作者的 `boot-dagu.img` 在 ramdisk 之后有一个 368 字节的 `AVB0` 结构
（原厂 `boot_a.img` 反而没有）。改 ramdisk 后该结构的 hash 失配；本包的做法是
**把 ramdisk 之后的区域全部保持为 0**（等价于原厂"无 footer"），配合 `vbmeta-disabled.img` 即可启动。

## 7. 各硬件实现细节

### 显示（L81A）
- `panel-xiaomi-dagu-l81a.c`（作者 overlay），双 DSI + DSC
- 复位 GPIO100（ACTIVE_HIGH）、`enp`/`enn`、`hwen` 全在 panel 驱动里
- 背光 KTZ8866（i2c9/i2c11 @0x11），`l81a-wled`，max_brightness 2047
- 手动调亮度：`write /sys/class/backlight/l81a-wled/brightness 2000`

### 触摸（Himax）
- `himax-dagu.c`，SPI GENI（`spi@990000`）
- `tp-reset-gpios` 归 panel 驱动（GPIO100），触摸节点**不要**再绑
- 中断用 `IRQ_TYPE_LEVEL_LOW`

### USB 3.1 / Type-C（已打通，见 §7.1）
- device（g_serial）、host（U 盘/键鼠）、PD 都可用；**USB 3.1 SuperSpeed 已启用**
- 关键在 QMP combo PHY 的供电与 dwc3 的 quirk，配置见下方 §7.1

### Wi-Fi（ath11k）
- 固件：`/lib/firmware/ath11k/QCA6390/hw2.0/{amss.bin, board-2.bin}`（Debian 包自带）
- **固件是 HST 测试版**（`WLAN.HST.1.0.1.r1-01134-...`，2024-02 编译），高通没为 QCA6390 发布过正式 HSP 版，换不了
- 正常速率：`960.7 / 864.8 Mbit/s`（80 MHz HE 2×2，国家码 CN 下；见 §6.5）
- **160 MHz 不可用**：CN 法规 80 MHz 上限 + ath11k HE 只到 80 MHz
- **两块禁地**：不要加 `pcie_aspm=off`（会导致速率协商退化）；不要让第二个 wpa_supplicant 抢接口（见 §8）
- **必须关闭自动挂起**，否则空闲 15 分钟后 Wi-Fi 会因 resume 失败变成"僵尸 6 Mbit/s"（见坑 11）

### 蓝牙
- 固件见 §6.2；`hci0` 状态应为 `UP RUNNING`、`Powered: yes`

### 音频
- 扬声器：CS35L41 ×4 走 I2S/TDM，**不经过 ADSP**
- UCM：`/usr/share/alsa/ucm2/Xiaomi-dagu/HiFi.conf`
  + `/usr/share/alsa/ucm2/conf.d/sm8250/Xiaomi-dagu-CS35L41-WCD9385.conf`
- 初始化脚本：`/usr/local/bin/dagu-audio-up.sh`（作者提供，需把内部 `dagu` 用户名改成实际用户）
- systemd 服务：`dagu-audio-up.service`（`User=youqi`、`SuccessExitStatus=1`，因为麦克风会失败）
- 若无声先查是否 MUTED：
  `su - youqi -c "XDG_RUNTIME_DIR=/run/user/1001 wpctl set-mute @DEFAULT_AUDIO_SINK@ 0"`

**⚠️ 两个必踩的坑（都会导致"完全无声"）**：

1. **CS35L41 固件必须落在 rootfs 的 `/lib/firmware/cirrus/`**
   作者只把固件放进了 **initramfs**，switch_root 到 rootfs 之后内核就找不到了：
   ```
   cs35l41: DSP1: Failed to request firmware <cirrus/>cs35l41-DSP1-spk-prot<-dagu<BL>>.wmfw
   ```
   驱动会按 speaker 位置拼名（`-dagu-BL/BR/TL/TR`），所以除了复制 22 个原始文件，
   还要给 4 个位置各建 3 个软链（`spk-prot.wmfw` / `spk-prot.bin` / `spk-cali.wmfw`）。
   本包的 `firmware/cirrus-full.tar.gz` 已经包含这些链接，`setup-system.sh` 会自动解压。
   成功标志：
   ```
   cs35l41 1-0040: DSP1: Firmware: 400a4 vendor: 0x2 v0.43.1, 2 algorithms
   cs35l41 1-0040: dagu: applied CAL_R=9696 ambient=23 SET_STATUS=2
   ```

2. **服务启动早于 `/run/user/1001` 创建**
   原始 service 挂在 `multi-user.target`，而 logind 要到用户会话（GNOME 登录）才建
   `/run/user/1001`。于是脚本里 `mkdir` 报 `权限不够`，整个路由没做，sink 存在但没声。
   修法（本包已含）：
   - service 加 `After=... user@1001.service` + `Wants=... user@1001.service`
   - 脚本开头等待 `/run/user/1001` 出现（最多 60 秒）
   - 麦克风重试从 20 次降到 3 次，避免服务卡在 `activating`

**已知不影响出声的报错**：
```
cs35l41: Direct firmware load for cirrus/BR-music.txt failed with error -2
cs35l41: dagu: fast-switch firmware cirrus/TR-music.txt: -2
cs35l41 1-0041: DSP1: Legacy support not available
```
`-music.txt` 是 DSP fast-switch 配置，设备任何分区里都没有；实测缺失时四个扬声器仍全部正常发声。

### GPU（Adreno 650）
- `adreno 3d00000.gpu`，加载 `a650_gmu.bin` + `a650_sqe.fw`
- GNOME 走 MSM DRM 硬件合成
- **没有 GPU 负载接口**（kgsl 的 gpubusy 是下游专有），资源监视器看不到占用是正常现象；
  可看 `/sys/class/devfreq/3d00000.gpu/cur_freq`（305 MHz 表示在跑）

### Venus（视频硬解）
- 模块：`venus-core.ko` / `venus-dec.ko` / `venus-enc.ko`（在 `/lib/modules/<ver>/extra/`）
- 手动加载：`modprobe venus-core && modprobe venus-dec && modprobe venus-enc`
- 开机自启：`venus-load.service`（本包提供）
- 节点：`/dev/video15`（dec）、`/dev/video14`（enc）
- 首次 probe 若报 `venus.mdt failed -2`，说明固件没放对；放对后会出现 SMMU fault 但 probe 成功

### 传感器 / 麦克风（当前无法实现）
- 传感器（LSM6DSO、TMD3719）物理挂在 **ADSP 的 SSP 私有总线**：
  - 原厂 AP DTB（4 个变体）**0 个 sensor 节点**
  - 原厂 QUP i2c（880000–99c000）**全 disabled**
  - Linux 里 `/sys/bus/iio/devices/` = 0
  - 新启用 6 条 i2c 扫描后也没有 0x6A/0x39
  - → 除非移植 ADSP SSP 协议栈，否则**自动亮度/自动旋转/霍尔永远不可用**
- 麦克风：WCD9385 capture 必须过 Q6 DSP，而 `q6asm-dai` 报 `DSP returned error[1]`
  （ADSP 固件 2024-03 与内核 7.0 的 q6asm ABI 不匹配）→ 播放（走 I2S）正常，录音不行

## 7.1 USB 3.1 打通实录（Type-C）

作者原版 dtb 把 USB 限在 **USB 2.0**（`maximum-speed = "high-speed"`、dwc3 只挂 `usb2-phy`），
QMP combo PHY（`phy@88e8000`）虽然节点存在，但 **`status = "disabled"` 且没有任何 supply**，
只能拿到 dummy regulator，所以 PHY 从未真正初始化。

### 原厂（stock.dtb）怎么接的

```
usb@a600000 (dwc3):   maximum-speed = "super-speed-plus"
                      dr_mode = "drd"
                      usb-phy = <两个 PHY>
                      snps,usb3-u1u2-disable        ← 下游专有
                      snps,disable-clk-gating
                      snps,has-lpm-erratum
                      snps,hird-threshold = [10]
                      tx-fifo-resize
phy@88e8000 (QMP):    compatible = "qcom,usb-ssphy-qmp-dp-combo"   ← 下游驱动
                      vdd-supply / core-supply
                      qcom,qmp-phy-init-seq = <几百个寄存器值>
```

### 三处修改（本包的 vendor_boot 已包含）

1. **给 QMP PHY 补真实供电**（决定性的一步）
   ```dts
   phy@88e8000 {
       status = "okay";
       vdda-phy-supply = <&vreg_l9a_1p2>;    /* 1.2V */
       vdda-pll-supply = <&vreg_l18a_0p9>;   /* 0.9V */
   };
   ```
   > 修复前 dmesg：`supply vdda-phy not found, using dummy regulator`
   > 修复后：`phy-88e8000.phy.0` / `.1` 两个 PHY 正常注册

2. **补上 mainline 版的 USB3 quirk**
   作者的 dtb 已有 `dis_u2_susphy` / `dis_enblslpm` / `dis-u1-entry` / `dis-u2-entry`，
   **唯独缺 `snps,dis_u3_susphy_quirk`**（原厂 `snps,usb3-u1u2-disable` 的核心部分）：
   ```dts
   usb@a600000 {
       snps,dis_u2_susphy_quirk;
       snps,dis_u3_susphy_quirk;          /* ← 必须补 */
       ...
   };
   ```

3. **挂上 USB3 PHY 并放开速度**
   ```dts
   phys = <&usb_1_hsphy>, <&usb_1_qmpphy QMP_USB43DP_USB3_PHY>;   /* cell 0 */
   phy-names = "usb2-phy", "usb3-phy";
   maximum-speed = "super-speed-plus";
   ```

### 验证

```bash
cat /sys/class/udc/*/maximum_speed      # super-speed-plus
echo host > /sys/class/usb_role/a600000.usb-role-switch/role
dmesg | grep -i xhci
#   xhci-hcd: Host supports USB 3.1 Enhanced SuperSpeed
lsusb
#   Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub   ← 关键
```

> `current_speed` 在 device 模式下显示 `high-speed` 是**正常的**：g_serial 是 USB2 gadget，
> 且对端 PC 口/线常常是 USB2。判断 USB3 是否启用看 **`maximum_speed`** 和 **`Bus 002 ... 3.0 root hub`**。

### 失败模式（重要）

只加 `phys = <... usb3-phy>` 而**不加供电或 quirk** 时，dwc3 初始化会 **hard hang**：
内核既没有 panic 也没有跑完，USB 全断（串口一起消失），`panic=10` 与 ABL retry 都不一定救得回来，
需要**长按电源 10 秒 → 音量下 + 电源**手动进 fastboot。

所以顺序必须是：**先单独开 PHY（只看它能否 probe）→ 再挂 dwc3 → 再放速度**，一次一个变量。

### DP（仍未打通）

DP 用的也是这颗 QMP combo PHY 的另一半（`phy-88e8000.phy.1`，已 probe），DP 控制器节点
`displayport-controller@ae90000` 本来就在 dtb 里（`status = "disabled"`），DPU 端点也已连好。缺的是：

- 内核 **`CONFIG_TYPEC_DP_ALTMODE` 未编译**，typec 不会协商 DP alt-mode
- 原厂 DP 节点**没有 `hpd-gpios`**，HPD 依赖中断/typec 上报
- 作者内核无法重编（14 个驱动无源码），所以这条路要等作者放出源码

`msm_dp` 驱动不支持 `no-hpd` 属性，因此无法强制点亮。

## 8. 踩过的坑

### 坑 1：`pcie_aspm=off` 让 ath11k 掉到 6 Mbit/s ⚠️⚠️
- 现象：`tx 6.0 / rx 48.0 MBit/s` + 66% 丢包（信号仍 -50 dBm，`tx failed 0`）
- 原因：mainline ath11k 依赖 PCIe ASPM，关掉后速率协商进入 legacy 1×1
- **永久禁止**在 cmdline 加这个参数。已加过的用 `vendor_boot-content.img` 刷回

### 坑 2：两套 wpa_supplicant 抢接口
- 现象：NM 日志 `wpa_supplicant couldn't grab this interface` → 重试 #5 → giving up → 链路半死（6 Mbit/s）
- 起因：`wpa_supplicant@wlp1s0.service` 仍 active，与 NM 自带实例抢 `wlp1s0`
- 修复：
  ```bash
  systemctl stop/disable/mask wpa_supplicant@wlp1s0
  pkill -9 wpa_supplicant
  systemctl restart NetworkManager
  ps aux | grep -c '[w]pa_supplicant'    # 必须 = 1
  ```

### 坑 3：DHCP 换 IP 被误判为"断网"
- 现象：ping 旧 IP 100% 丢包，以为网络挂了
- 实际：IP 在 `.123 / .125 / .240` 之间变过多次
- 排查顺序：**先 `ip -br a` 看真实 IP**，再判断死活

### 坑 4：SSH host key 变了
重装 rootfs 后 host key 变化 → `Host key verification failed`：
```bash
ssh-keygen -R <ip>
ssh -i key -o StrictHostKeyChecking=no root@<ip>
```

### 坑 5：suspend 唤醒后 ath11k 崩
- `PM: suspend exit` 正常（能唤醒），但同一时刻 `ath11k: PMF QOS (-108 ESHUTDOWN)`
- 之后 `wlp1s0: disconnected`，**无法重连**（固件已 shutdown），只能重启
- 规避：电源键改 `power-button-action=interactive` + `HandlePowerKey=lock`（锁屏不 suspend）

### 坑 6：USB 串口（g_serial）内建，卸不掉
- `g_serial` 是 `=y`，`rmmod` 报 "Module unloading is not supported"
- 后果：UDC 被长期占用，`usb-gadget.service`（RNDIS）永远 failed
- 好处：串口（COM4 @115200）**永远可用**，是救砖的主通道

### 坑 7：串口传文件会导致设备重启
- 用 `send_file_com.ps1` 传大文件（>1 MB）时，串口写满会触发设备重启
- 属正常现象，重启后文件已完整（md5 校验过）

### 坑 8：大文件 scp 会被截断
- 10.7 GB tar：传 3 分钟只到 546 MB；拆 1 GB 段：单段 851 MB 仍截断
- 结论：这条 Wi-Fi 链路（12 MB/s）不适合大文件传输；rootfs 全量备份改用"重建"路径

### 坑 9：fastboot 大镜像 OOM
- `fastboot flash userdata dagu-rootfs.img`（8 GiB）→ `std::bad_alloc`
- 解决：转 sparse（`simg2img` 反向操作 / 自写 Python 转换）或缩小到 1.5 GiB

### 坑 10：`fastboot erase dtbo_b` 无效
dagu ABL 不会因 erase 跳过 DTBO 校验，必须刷合法 stub（`dtbo-stub.img`）

### 坑 11：空闲 15 分钟自动挂起 → Wi-Fi 变"僵尸 6 Mbit/s" ⚠️⚠️
- 现象：放着不动十几分钟后网络断，重启才恢复；`iw link` 显示还在"关联"，但 tx 只有 6 Mbit/s
- 真相（dmesg + journal）：
  ```
  sleep-inactive-ac-type = 'suspend'，timeout = 900
  ieee80211 phy0: PM: dpm_run_callback(): wiphy_resume returns -108
  ieee80211 phy0: PM: failed to resume async: error -108
  ```
  即**自动挂起后唤醒时 ath11k 固件已经 ESHUTDOWN**，接口留在半死状态
- 修复（配置层，不需要刷 boot）：
  ```bash
  su - youqi -c "XDG_RUNTIME_DIR=/run/user/1001 gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type nothing"
  su - youqi -c "XDG_RUNTIME_DIR=/run/user/1001 gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-battery-type nothing"
  ```
- 同一 bug 也意味着 **按电源键 suspend 不可用**（唤醒必断网），电源键策略应设为锁屏

### 坑 12：`iw reg set CN` 无效，必须走 cmdline + initramfs
见 §6.5。根因是 `cfg80211` 在 initramfs 阶段加载 `regulatory.db` 时 `-2`，
没有国家表时用户态 hint 被静默丢弃。`wireless-regdb` 装不装都一样。

### 坑 13：重打包 initramfs 会静默产出坏包
`gzip -t` 通过不等于可用：曾出现 cpio 流截断但 gzip 校验正常的包，刷进去 ABL 直接回退 a 槽。
**必须用 `cpio -t | wc -l` 校验条目数**（原包 166，加 regdb 后 168），并确认 `init`、`sbin/init` 都在列表里。

### 坑 14：改 dwc3 的 USB3 会 hard hang（控制面全灭）
现象：刷入后设备完全离线（COM4/adb/fastboot 都没有），等 2-3 分钟才可能被 ABL retry 拉回 recovery。
根因：QMP PHY 没有真实供电（dummy regulator）或缺少 `dis_u3_susphy_quirk` 时，
dwc3 初始化会死等 PHY，内核既 panic 不了也跑不完。
**正确顺序**：先只开 PHY 看它能否 probe（`/sys/class/phy/phy-88e8000.phy.0` 出现）
→ 再挂 `usb3-phy` + quirk → 最后才 `super-speed-plus`。一次只改一个变量。
`panic=10` 和 ABL retry 对这类 hang **不可靠**，物理按键是最后防线。

### 坑 15：逆向原厂固件的正确入口
小米按 GPL 公开了内核源码（`MiCode/Xiaomi_Kernel_OpenSource`，dagu 对应分支 `dagu-s-oss`），
但**高通 BSP 的 vendor dts 不在其中**（`arch/arm64/boot/dts/vendor/qcom/` 不存在），
所以 dts 层面拿不到"标准答案"。真正有用的是**设备自己的 stock.dtb**：
```bash
# 从 vendor_boot_a.img 提取（header 2112，vendor_ramdisk_size 在 offset 24）
dtc -I dtb -O dts -o stock.dts stock.dtb
```
里面能读到原厂 dwc3/QMP PHY 的完整属性（`snps,usb3-u1u2-disable`、`qcom,qmp-phy-init-seq` 等），
再映射到 mainline 的等价 quirk（见 §7.1）。**这比反编译内核二进制有效得多**。

> 前提：BL 已解锁（`fastboot getvar unlocked` = yes）。**只在 b 槽操作，a 槽原厂系统保留作救援。**

### 第 0 步：准备
```powershell
# 用 Google platform-tools 37（不要用小米的 fastboot）
# 进入发布包目录
cd dagu-debian-20261020
```

```powershell
# 只刷 boot 链，保留现有 userdata
.\install\flash-rom.ps1 -Fastboot "C:\platform-tools\fastboot.exe" -SkipUserdata

# 完整安装（含 rootfs，会清空 Android /data）
```

### 手动刷写（等价）

```powershell
$F = "platform-tools\platform-tools\fastboot.exe"
adb reboot bootloader
& $F devices
& $F flash boot_b          images\boot-dagu.img

& $F flash vbmeta_b        images\vbmeta-disabled.img

& $F reboot
```

### 第 3 步：首次启动（约 2–3 分钟）
- 内核启动 → initramfs 挂 userdata → `e2fsck + resize2fs` 到 105 GiB → switch_root

### 第 5 步：系统配置

## 11. 回滚与救援

**分层锚点**（`16-anchor/`，本包 `config/` 是同一份）：

| 症状 | 回滚层 | 操作 |
|---|---|---|
| 电源键/网络管理/服务异常 | 配置层 | 解开 `config/anchor-cfg-*.tar.gz` 覆盖 + `daemon-reload` |
| 起不来、黑屏、fastboot 回退 | boot 层 | `fastboot flash` 四个镜像刷回 |
| 系统崩、apt 坏了 | rootfs | 重刷 `rootfs-1.5g.img` 再按 §5 重建 |
| Wi-Fi 6 Mbit/s | cmdline | 查 `/proc/cmdline` 有 `pcie_aspm=off` 就刷回 `vendor_boot-dagu.img` |

**救砖通道**：
1. **串口**（g_serial，永远可用）：`send_com.ps1` / `read_com.ps1`
2. **fastboot**：长按电源 10 秒 → 音量下 + 电源
3. **a 槽原厂系统**：`fastboot set_active a` 随时可回（原厂 boot/vendor_boot/vbmeta 未动）
4. **EDL**：QFIL + 原厂包（最后手段）
